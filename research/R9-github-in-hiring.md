# R9 — «개발자 채용에서 GitHub 제출이 기본 절차가 되었다» 근거

> 조사일 2026-11-08 · 요청: ppt-start · Sonnet Worker 2개 + Opus 직접 재확인
> 표기 (R1~R8과 같음):
> - **✅** 원문을 열어 숫자를 확인했다
> - **✅★** Opus가 이번에 다시 열어 문구까지 대조했다
> - **📰** 검색 요약이나 2차 인용만 확인했다
> - **⚠** 보고서 수치와 다르거나 불명확하다
> 덱·claims.md·최종보고서는 열지 않았다.

## 한눈에 — 판정

**«기본 절차가 되었다»는 국내·해외 어디에서도 직접 근거가 없다. 이 표현은 쓰지 말 것.**

| 질문 | 답 |
|---|---|
| 공고·지원서에서 GitHub를 요구·우대하는 비율 | **못 찾음** (원티드·점핏·잡코리아·사람인 모두) |
| GitHub만으로 지원받은 기업 사례 | **있음 (11-08 재탐색).** 토스 프론트엔드가 2025-04-08~05-31에 «이력서 없이 GitHub 리포지토리 링크로 지원하기» 전형을 운영했다. 프론트엔드 리더가 «오직 코드를 기준으로 평가» ✅★ — 1-1절 |
| 채용 담당자가 GitHub를 «눈여겨보는» 비율 | **있음.** 프로그래머스 2023: 이력서에서 눈여겨보는 항목 2위 «개인 깃허브» **56.8%** (n=241) ✅ |
| 반대 근거 | **있음.** 원티드 2023: 채용 평가 중요 요소에서 면접관의 깃헙 선택은 **20.3%(9개 중 7위)**로, 지원자 예상 34.2%보다 낮다 ✅★ |
| 해외 | GitHub를 «기본 절차»로 보여 주는 수치는 없다. CodePath 2025: 엔지니어링 리더 222명 중 **34%**가 면접 외 준비도 신호로 «GitHub 같은 공개 코드 포트폴리오»를 꼽았다 ✅★ |

→ 근거가 받쳐 주는 범위는 «GitHub는 많은 채용 담당자가 *참고*하는 자료»까지다. «필수 제출»이나 «기본 절차»는 근거 밖이다.
→ 덧붙여, 같은 원티드 조사에서 면접관이 가장 중시한 요소는 **커뮤니케이션 77.6%, 프로젝트 경험 75.0%**다. 「저장소 자체」보다 「프로젝트 경험」을 본다는 데이터라 Devfit 논지에는 이쪽이 더 잘 맞는다.

## 1. 국내 — 공고·지원서 구조

| 항목 | 결과 | 상태 |
|---|---|---|
| 개발 공고 중 GitHub·포트폴리오 링크 요구·우대 비율 (원티드·점핏·잡코리아·사람인·프로그래머스 커리어) | 통계 없음 | 못 찾음 |
| 이력서 양식에 GitHub 전용 칸이 기본으로 있는지 | 도움말·가이드 페이지에서 확인하지 못함. 공개 가이드 수준에서는 «홈페이지 주소: 포트폴리오 링크 (깃허브, 노션 등)»처럼 일반 링크 칸으로 안내한다 | 못 찾음 |
| 공고 표본 세기 | 수행하지 않음 | — |

→ «구조적 사실»로 기록할 수 있는 것은 없다. 원하면 사람이 점핏·원티드 이력서 작성 화면을 열어 GitHub 칸이 있는지 직접 보는 게 가장 빠르다 (로그인 필요, 2분).

| 확인 못 한 것 | ① 이 전형으로 **실제 합격자가 나왔는지**(후기·발표 못 찾음) ② 리포 통과 뒤 이후 전형(면접 등) ③ 신입/경력 대상 ④ 자기소개서 언급 — 원문은 «이력서 없이»이고 «자소서»라는 단어는 없다 |

**참고 — 토스 2020 NEXT 개발자 공채** ✅: "서류 평가 절차를 없애고 모든 지원자가 코딩테스트를 통해…", 이력서·포트폴리오는 "코딩테스트 합격자에 한해" 제출. GitHub 언급은 없다. https://toss.im/tossfeed/article/next-developer-recruitment-2020 (2020-07-20)

→ 쓸 수 있는 표현: «토스는 2025년 프론트엔드 채용에서 이력서 없이 GitHub 리포지토리 링크만으로 지원받는 전형을 열었다.»
→ 쓰면 안 되는 표현: «토스가 깃헙 링크로만 **뽑았다**»(합격 사실 미확인) · «자소서 없이»(원문은 «이력서 없이») · «업계 표준/기본 절차»(한 기업 한시 전형)

## 보고서용 안전한 한 문장 + 각주

**권장 문장:**
> «개발자 채용 담당자의 과반(56.8%)이 이력서에서 개인 GitHub를 눈여겨본다고 답했다. 다만 면접관이 실제로 가장 중시하는 것은 저장소 자체보다 *프로젝트 경험*(75.0%)이다.»

**각주:**
- ¹ 프로그래머스 「2023 개발자 채용 트렌드」 설문, 2023-01, 채용 담당자 241명(HR 143·개발자 98), 복수응답. https://programmers.co.kr/pages/2023-recruiting-survey
- ² 원티드 「개발자 리포트」(2023-01) «채용 평가 시 중요 요소» 면접관 답변. 같은 조사에서 깃헙은 20.3%(7위). https://static.wanted.co.kr/images/data_report/Wanted_report_developer.pdf

**사례 문장(선택):**
> «토스는 2025년 프론트엔드 채용에서 이력서 없이 GitHub 리포지토리 링크만으로 지원받는 전형을 열고, 리더들이 코드만으로 평가했다.³»
- ³ 토스, 「토스 프론트엔드에 이력서 없이 리포지토리 링크로 지원하세요」, 2025.

**쓰지 말 것:**
- «GitHub 제출이 기본 절차가 되었다» / «필수가 되었다»: 공고·양식 통계가 없다
- «토스가 깃헙 링크로만 뽑았다» / «자소서 없이»: 합격 사실 미확인, 원문은 «이력서 없이»
- «2020 37.9% → 2023 56.8%로 증가»: 문항이 다르다
- 2024년 이후 수치처럼 쓰기: 국내 수치는 모두 2023년 초 이전이다

**R8 정정 연계:**
- R8 5번(프로그래머스)은 «삭제 권고» → **«그대로(56.8%)»로 복구**한다
- 보고서의 «역량 검증 53.4%»는 **52.7%로 수정**한다 (1위 «적합한 인재탐색» 69.3% 다음 2위)
