**교정안 하나 (가설): 인앱 브라우저를 감지해 외부 브라우저로 넘기기**
- Instagram·Facebook 인앱 UA를 감지한다. Android는 `intent://`로 Chrome을 바로 열고, iOS는 «Safari에서 열기» 안내 바를 띄운다. 넘어가기 전 첫 화면에서는 비로그인 체험(공고 URL 붙여넣기)을 먼저 보여 준다
- 근거: 인앱 웹뷰에는 GitHub 로그인 세션이 없다. 그래서 GitHub OAuth를 하려면 비밀번호와 2FA를 새로 입력해야 한다(미검증 가설. 05·04 문서의 원인 후보와 같다). LCP·#418 오류도 인앱에서 몰려 있다
- 기대 효과(가설): Instagram 전환율 0.10~0.15% → **0.25~0.40%**. 다른 유입(1.2~1.5%)보다는 여전히 낮게 잡았다. 광고 대상층의 의도가 다르기 때문이다. 9~10월 Instagram 세션 19,980개에 적용하면 가입 **+21~+60명** (주 +2.4~+6.9명)
- 검증 방법: Clarity에서 브라우저=Instagram으로 필터해 `/login` 도달률과 녹화를 본다 → 수정 후 2주 A/B(인앱 UA 절반만 리다이렉트)
- 덱 활용: p17 «우리가 찾은 약점 → 다음 조치». 수행과정 20(«원인을 숫자로 좁혔다»)
- 주의: **월 비교는 자연 실험이지 통제 실험이 아니다.** 8월에는 팀·멘토가 가입했고 11월은 표본이 작다. 인앱 비중과 광고 유입이 같이 움직이므로 «인앱 탓»과 «광고 대상층 품질 탓»을 아직 분리할 수 없다 → 장표에서는 «가설»로 표기한다
