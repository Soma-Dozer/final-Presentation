## 0. 결론 먼저

1. **7일 안에 «기업이 서명한 LOI»가 나올 확률은 낮다.** 결정권자 접점이 바삭한소프트 김준엽 대표 1명뿐이고, 그도 «이미 Claude Code로 GitHub를 검토한다»는 반론을 냈다. 현실적인 7일 목표는 **① 비구속 «파일럿 참여 의향서» 1건(시도) + ② 현직 면접관 «평가 의견서» 1~2건(가능성 높음)**이다. 둘은 성격이 다르니 덱에서 섞지 않는다.
2. **7일 파일럿은 «실전 채용»이 아니라 «회고형»으로 설계해야 성립한다.** 실제 지원자를 받으려면 운영 B2B 공개·위탁 계약·처리방침 정비가 먼저인데, 그건 7일 안에 안 된다(§2-3 전제). 대신 **공고 1건 + 동의한 사람의 공개 레포 3개 → 면접 브리프 → 면접관이 질문마다 «실제로 쓰겠다/모르겠다/안 쓰겠다»를 표시 + 그 회사가 쓰는 방식(Claude Code)과 나란히 비교** — 30분 세션이면 끝나고, 그 결과가 곧 증거다.
3. **바삭한소프트에는 «우리 제품 소개»가 아니라 «대표님이 말한 반론을 같은 레포로 직접 비교해 보자»로 간다.** 이미 실측이 있다(`E-compare.md`: 링크만 받은 범용 AI 근거 0/18 실존, 레포를 읽은 Claude Code 30/32, DevFit 28/28). 그 반론에 답하는 것이 LOI로 가는 유일한 길이다.
4. **p24는 LOI가 오든 안 오든 정직하게 쓸 수 있게 두 벌을 준비한다**(§4). «고객 확보»·«파일럿 진행 중»은 어떤 경우에도 금지.

## 2. 무료 파일럿 제안서 (1장) — 그대로 PDF로 만들 수 있게

> **DevFit 면접 브리프 무료 파일럿 (디자인 파트너)**
> 지원자를 채점하지 않습니다. 면접관을 준비시킵니다.

### 2-1. 무엇을 해 드리나

지원자가 **동의하고 제출한** 공개 GitHub 저장소에서, 지원자 **본인이 작성한 커밋·변경분**만 골라 «이 사람 코드에서 물어볼 만한 지점»을 질문으로 정리한 **면접 브리프**를 드립니다. 질문마다 근거 커밋·파일이 붙고, 근거가 코드에 실제로 없으면 서버가 그 질문을 버립니다.

### 2-2. 두 단계

| | **1단계 — 회고형 (7일)** | **2단계 — 실전 (4~8주, 1단계 후 선택)** |
|---|---|---|
| 대상 | 공고 1건 + 공개 레포 **3개** — 귀사 엔지니어 중 자원자 본인 레포, 또는 귀사가 고른 오픈소스 레포 | 실제 채용 공고 1건, 지원자 **최대 20명** |
| 진행 | DevFit 팀이 브리프를 만들어 화면 공유 → 귀사 면접관 1~2명이 30분 동안 질문마다 표시 | 공개 지원 링크로 접수(지원자 동의 2건 + 이메일 인증) → 면접 전 면접관이 브리프 사용 |
| 귀사 비교 | **같은 레포를 귀사가 지금 쓰는 방식(예: Claude Code에 링크 전달)과 나란히** | 기존 면접 준비 방식과 비교 |
| 귀사 부담 | 30분 1회 | 면접관 설문 2회(각 5분) |
| 비용 | 무료 (분석 원가 DevFit 부담) | 무료 |

### 2-3. 무엇을 재나 — 성공 기준은 시작 전에 고정한다

| 지표 | 1단계 기준 | 2단계 기준 |
|---|---|---|
| 질문 근거 실존율 (근거 커밋·파일이 실제로 있는가) | 100% (서버 검증) | 100% |
| **면접관 채택률** — «실제 면접에서 쓰겠다» 표시 비율 | ≥ 50% | 실제 면접에서 1개 이상 사용한 지원자 비율 ≥ 50% |
| 귀사 기존 방식과 비교 — 면접관이 «더 쓸 만하다»고 고른 쪽 | 기록만 (승패 주장 안 함) | — |
| 면접 1건 준비 시간 (면접관 자가 기록, 전/후) | — | 기록만 |
| 지원자 동의 철회·이의 제기 건수 | — | 기록·공개 |

⛔ 이 파일럿은 **채용 결과(합격률·성과)가 좋아진다는 것을 보여 주지 않습니다.** 그건 아직 검증되지 않았고(H2 미실증), 파일럿 규모로는 잴 수 없습니다.

### 2-4. 하지 않는 것 · 데이터 처리

- **합격·불합격, 순위, 점수를 내지 않습니다.** 최종 판단은 면접관이 합니다.
- **«AI로 작성했는지」를 판정하지 않습니다.** 브리프는 «추가로 물어볼 가치가 있는 지점」만 안내합니다.
- 지원자 **모르게 분석하지 않습니다.** 1단계는 레포 주인 본인 동의, 2단계는 지원 화면에서 동의 2건을 받습니다. **지원자가 내지 않은 레포를 귀사가 붙여 넣는 방식은 쓰지 않습니다.**
- **공개 저장소만** 다룹니다. 비공개 저장소는 파일럿 범위 밖입니다.
- 분석 데이터는 **AI 모델 학습에 쓰지 않습니다.** 분석에 쓰는 AI는 AWS Bedrock(미국 동부·서울 리전)에서 돌며, 2단계 시작 전 국외 이전 항목을 지원자 고지에 명시합니다.
- 2단계에서 귀사는 개인정보 **처리자**, DevFit은 **수탁자**입니다 → 시작 전 **처리 위탁 계약**을 맺습니다.
- 파일럿 종료 후 **30일 안에 지원자 데이터를 파기**하고 결과를 서면으로 알려 드립니다. 요청하시면 그 전에라도 바로 지웁니다.
- 파일럿 결과를 저희 발표·보고서에 쓸 때는 **귀사가 고른 표기(실명 / «IT 기업 A»)**만 씁니다.

### 2-5. 2단계 전에 DevFit 쪽이 먼저 끝낼 일 (내부용 — 제안서엔 넣지 않는다)

1. 운영 B2B 공개(`PRODUCTION_B2B_ENABLED`) 또는 파일럿 전용 접근 경로 결정

| 리스크 | 대응 |
|---|---|
| 7일 내 회신 0 | B안으로 간다. «제안 n곳 · 회신 대기」는 사실이면 써도 된다. **억지로 지인 회사(VERTEX 등) LOI를 받지 않는다** — 이해관계자 LOI는 심사에서 역효과 |
